HOW I WORK WITH AI

An algorithm, not a vibe.
This is the loop I run.

Most data-science workflows stop at a notebook. Mine ships into production because every step has a gate — a spec, a test, a review, an observable system — and AI agents do the heavy work inside those gates.

  1. FRAME — WITH THE OPERATOR. Frame the problem with the operator, not the dataset.
  2. SPEC — DESIGN BEFORE CODE. Write the spec before any code.
  3. PLAN — REVIEWABLE UNITS. Decompose the spec into a reviewable plan.
  4. BUILD — TESTS WITH THE CODE. Build with agents — code and tests produced together, every step reviewable.
  5. VERIFY — MULTI-GATE. Verify against a stack of gates — types, lint, tests, eval/regression, secrets check, human review.
  6. SHIP — RELEASE-TAGGED. Ship with a release tag and a written rollback path.
  7. OBSERVE — LOGS & FEEDBACK. Observe in production — logs, traces, and incident feedback drive the next loop.

Three explicit gates: after SPEC the spec must be clear or work returns to SPEC; after VERIFY the multi-gate check must pass or work returns to PLAN; after OBSERVE production must be healthy or the next loop starts at FRAME.
